Local dictation for Windows, macOS and Linux

Hold a button. Talk. It types where the cursor is.

type4voices runs the Qwen3-ASR speech model on your own CPU. Audio stays on the machine, dictation works with the network off, and the text is pasted into whichever window has focus. The default trigger is the Forward mouse button.

Python 3.10+ · 4.4 GB model, downloaded once · Apache-2.0 weights

What it does

Every item below is a setting in config.json, an entry in the tray menu, or both.

The trigger
Hold the shortcut to record, let go to transcribe. A tap shorter than a second is ignored, and a recording stops itself at two minutes.
The lamps
The tray icon is two lamps. Green while recording or transcribing, red while idle, both dark while paused. You can see whether the microphone is open without opening a window.
The panel
Small strip in the corner: timer first, transcript after. Click it for the history, right-click to copy the whole history. It never takes keyboard focus.
The clipboard
Each transcript stays on the clipboard after it is pasted. Left-click the tray icon to see the last five clipboard entries, then click one to copy it back.
The cleanup
Spoken numbers and punctuation become characters and filler words are dropped before the paste. Rules, not a second model, with about sixty unit tests behind them.
The recorder
Tray → Shortcut → Detect a new shortcut, then press what you want: a mouse button, F8, or something like Ctrl+Alt+J. It applies immediately, no restart.
The suppression
On Windows the shortcut is swallowed before the focused app sees it, so the side button stops navigating your browser. macOS and Linux can only observe it, which the platform table below explains.

One process on your computer, no server

The same Python runs on all three systems. The differences live in platform_support.py: paste chord, clipboard tool, panel flags and autostart. On Windows, trigger.py installs low-level hooks so the shortcut can be swallowed. The other two use a pynput listener and leave the original event alone. 

# one dictation, start to finish
shortcut down   recording starts, audio frames go to a buffer
shortcut up     silence trimmed, duration checked, job queued
worker thread   transcribe, clean up the text, paste into the focused window
clipboard watch new transcript added to the left-click history

Only one transcription runs at a time, so quick dictations queue instead of fighting for the CPU. The tray icon appears before the model finishes loading.

Set up once, then work offline

You need Python 3.10 or newer, a microphone, and about 6 GB of disk, most of it the model. Everything installs into .venv at the top of the folder, whichever system you are on.

Windows

Python 3.12 from python.org, PATH enabled

  1. Run the setup file once. It creates the environment and installs the pinned packages.
  2. Download the weights. That is the only step that needs internet.
  3. Start it, then pin the tray icon to the taskbar so it stays visible.
windows\setup.bat

.venv\Scripts\python.exe download_model.py

windows\run_dictate.bat              # console window
windows\run_dictate_background.vbs   # no console

macOS

Python 3.12 from python.org, the system one has no tkinter

  1. Run setup in the macos folder, or double-click run_dictate.command later if you prefer Finder.
  2. Allow Microphone, Accessibility and Input Monitoring when macOS asks, then restart the app.
  3. Turn Handoff off if you do not want dictated text reaching your other Apple devices.
cd macos
chmod +x *.sh run_dictate.command
./setup.sh
cd ..

.venv/bin/python download_model.py
./macos/run_dictate.sh

Linux

X11 session, Python 3.11+, PortAudio

  1. Install the system packages, then run setup in the linux folder.
  2. Log in to X11 or Xorg. Wayland blocks global hooks, synthetic keystrokes and tray icons for ordinary applications.
  3. Use xclip, xsel or, on Wayland, wl-clipboard for clipboard access.
sudo apt install python3 python3-venv \
  python3-tk libportaudio2 xclip

cd linux
chmod +x *.sh
./setup.sh
cd ..

.venv/bin/python download_model.py
./linux/run_dictate.sh

Later starts take a few seconds, and a background instance stays warm all day. The model loads once and sits in RAM: 4.4 GB for the 1.7B model, 1.2 GB for the 0.6B one. Installing the XPU build of torch moves inference to an Intel Arc GPU if you have one.

Questions

Does my voice or my text leave the machine?

No. The model is downloaded once by download_model.py, and from then on the app runs with HF_HUB_OFFLINE=1 and TRANSFORMERS_OFFLINE=1. Audio sits in memory as float32 frames, goes into the local model, and comes back as text.

Why does the side button no longer go Back or Forward in my browser?

On Windows a low-level mouse hook sees the click first and returns before the message reaches the browser. It is the same mechanism that records the clip, so suppression and dictation are one event. macOS and Linux can observe the shortcut but not remove it.

Where does the text actually land?

On the clipboard, followed by a synthetic Ctrl+V, or Cmd+V on macOS, sent to whichever window has focus. The transcript panel is built with non-activating flags so it cannot pull focus away while that happens.

Can I dictate into an administrator window on Windows?

Not from a normal user session: Windows blocks synthetic keystrokes from a lower integrity process to a higher one. Use Restart as Administrator in the tray menu for elevated consoles and tools.

Why X11 and not Wayland on Linux?

Wayland does not let an unprivileged background app read global keys and clicks, inject keystrokes into other windows, or draw a tray icon. The X11 path works today. dictate.py --doctor tells you which session you are in.

How do I get names and jargon right?

Add one term per line to hotwords.txt, for example PostgreSQL or OAuth2. The list is passed to the model as context and reloaded when the file changes, so names come back the way you wrote them.

Can I use a keyboard shortcut instead of a mouse button?

Yes, and the recorder refuses bare letters on purpose: a lone J would fire while you type normally. Use a modifier, as in Ctrl+Alt+J, or a function key such as F8. The choice is saved to config.json and applies without a restart.

Do I have to install anything else to send it to someone?

The code is in one repository, the weights are not. Copy the model cache directory to the other machine and point HF_HOME at it, or run download_model.py there once. GitHub cannot host a 4.4 GB release asset, so the cache is the practical way to hand over an offline copy.
